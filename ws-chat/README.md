# ws-chat

## Запуск

```bash
cd ws-chat
cp .env.example .env
npm install
npm run dev     # http://localhost:3000
npm start       # прод
```

С других устройств в LAN: `http://<ip-хоста>:3000` (сервер слушает `0.0.0.0`).

## Конфигурация

| Переменная | По умолчанию | Назначение                        |
|------------|--------------|-----------------------------------|
| `PORT`     | `3000`       | Порт HTTP/WebSocket-сервера.      |
| `HOST`     | `0.0.0.0`    | Адрес привязки (LAN — `0.0.0.0`). |
| `TLS_KEY`  | —            | Путь к приватному ключу (включает HTTPS). |
| `TLS_CERT` | —            | Путь к сертификату (включает HTTPS). |
| `DATA_DIR` | `./data`     | Каталог для истории (`store.json`), аккаунтов, сессий, вложений и ключа. |
| `UPLOAD_KEY` | —          | Ключ шифрования вложений, 32 байта в hex. Не задан — генерируется в `DATA_DIR/upload.key` (права 600). |

История пишется через временный файл с переименованием и сбрасывается на диск
при остановке сервера. Испорченный `store.json` не затирается, а откладывается
рядом как `store.json.corrupt-<время>`.

**Мастер-ключ должен пережить перезапуск** — без него не открыть ни вложения, ни
историю переписки. Он лежит в `DATA_DIR/upload.key`; если каталог данных не
переживает деплой, задавай `UPLOAD_KEY` явно. Потеряешь ключ — данные не
восстановить: сервер об этом честно скажет в лог и откажется сохранять поверх,
чтобы не затереть то, что ещё можно спасти правильным ключом.

## Что лежит на диске

| Файл | Содержимое | Как защищено |
|---|---|---|
| `store.json` | вся переписка, каналы, реакции | AES-256-GCM на ключе, производном от мастер-ключа |
| `uploads/*` | вложения | AES-256-GCM на мастер-ключе, имя файла — HMAC от содержимого |
| `accounts.json` | ники, scrypt-хэши паролей | права 600; пароль не восстановить и без шифрования |
| `sessions.json` | ники, sha256 токенов | права 600; по хэшу токена войти нельзя |
| `upload.key` | мастер-ключ | права 600 |

История и вложения шифруются **разными** ключами: у истории он выводится из
мастер-ключа через HMAC. Так утечка одного не раскрывает второе, и при этом
ключ по-прежнему один — хранить и переносить надо только его.

Аккаунты и сессии намеренно не шифруются: там нет ничего, что шифрование
защитило бы дополнительно — пароли уже необратимо посолены и прогнаны через
scrypt, а от токенов хранятся только хэши.

Старый незашифрованный `store.json` подхватится как есть и запечатается при
первом же сохранении — отдельная миграция не нужна.

## Вход

Два способа: **гостем** и **с паролем**.

**Гость** называет только ник. Личность переживает и перезагрузку страницы, и
перезапуск сервера, а заканчивается двумя способами: по кнопке «Выйти» или сама
собой, если гостем сутки не пользовались. Второе важно: вкладку закрывают гораздо
чаще, чем жмут «Выйти», и без срока годности ник оставался бы занятым навсегда.

В обоих случаях гость стирается целиком — аккаунт, все его сессии, сообщения в
каналах, обе стороны личной переписки, его реакции и вложения. Заодно вычищаются
снапшоты цитат: они специально переживают обычное удаление сообщения, и без этого
текст стёртого гостя остался бы висеть в чужих ответах. Ник освобождается,
вернуться в ту же личность нельзя.

Сутки отсчитываются от последнего использования, а не от входа: пока гость
заходит, срок сдвигается. Открытая вкладка тоже считается активностью — уборка
не трогает тех, кто сейчас в сети.

**С паролем** ник закрепляется навсегда, история переживает выход, а выход гасит
только текущую сессию. Гостем такой ник занять уже не получится.

Аккаунт можно держать открытым на нескольких устройствах разом: они не выбивают
друг друга, в списке участников ник показывается один раз, а «вышел» объявляется
только когда отключилось последнее устройство. Личные сообщения приходят на все.
Голос при этом одноустройственный: вход в голосовой канал с нового устройства
выводит из него прежнее, иначе два микрофона одного человека дают эхо, а
сигналинг, адресованный по нику, не смог бы выбрать между ними. Прежнее
устройство получает `voice-left` и сворачивает своё соединение.

Звонок, наоборот, звонит на все устройства адресата разом. Кто первым взял
трубку, тот и говорит: остальным приходит отбой с причиной `answered-elsewhere`.
Отказ на любом устройстве отменяет звонок целиком. После приёма сигналинг идёт
не по нику, а между двумя конкретными соединениями — иначе SDP мог бы уехать на
устройство, которое трубку не брало.

Пароль меняется в настройках: нужен текущий, новый берёт свежую соль, и все
остальные сессии гасятся — если старый пароль увели, открытое под ним в других
местах доверия больше не заслуживает. Сессия, с которой меняли, остаётся, иначе
меняющий выбьет сам себя. Там же список **устройств**: где сейчас открыт аккаунт, когда им пользовались в
последний раз, и кнопка отозвать любое по отдельности — отозванное сразу
отключается и по его токену больше не войти. Рядом **выйти со всех устройств**,
если проще погасить всё разом, включая текущее.

Метка устройства («Mac», «iPhone») определяется на клиенте и приходит вместе со
входом. Наружу отдаётся только публичный идентификатор сессии — хэш токена
клиент не видит, и отозвать чужую сессию, подобрав идентификатор, нельзя:
проверка идёт в пределах своего ника.

Как это устроено:

- Пароль хранится в `accounts.json` как scrypt (N=2^15, r=8) с индивидуальной
  солью, сверяется через `timingSafeEqual`. Проверка стоит ~100 мс — вход этого
  не замечает, перебор дорожает на порядки.
- Вход под несуществующим ником всё равно прогоняет KDF по «пустышке», чтобы по
  времени ответа нельзя было понять, какие ники заведены. Ответ на неверный ник
  и на неверный пароль одинаковый.
- Серия промахов замедляет вход по этому нику с нарастанием до 15 минут.
- Сессия — случайный токен, на сервере в `sessions.json` лежит только его
  sha256. Утёкший файл сессий не даёт войти ни за кого. Клиент держит токен в
  `localStorage`, поэтому пароль спрашивается один раз.
- Сессия живёт 30 дней у аккаунта с паролем и сутки у гостя, срок продлевается
  при каждом использовании. На аккаунт хранится не больше 10 сессий — самые
  старые вытесняются, чтобы вход с десятка устройств не копился бесконечно.
- Протухшие сессии, брошенные гостевые аккаунты и счётчики неудачных входов
  подчищаются раз в пять минут. Счётчики промахов вдобавок ограничены по
  количеству: иначе перебор случайных ников медленно съедал бы память.
- `accounts.json` и `sessions.json` пишутся с правами 600 и атомарно.

**Пароль идёт по тому же сокету, что и чат.** По `http://` его видит любой, кто
слушает сеть, — на экране входа об этом висит предупреждение. Гостевого входа
это не касается. Нормальное решение — поднять сервер по HTTPS (см. ниже);
вариант с SRP, при котором пароль вообще не покидает устройство, пока в планах.

## Каналы и сообщения

Discord-подобный текстовый костяк:

- **Именованные текст-каналы** (по умолчанию `general`, `random`) + создание и удаление из сайдбара (удаление уносит историю канала, последний канал не удаляется, всего каналов не больше 100); отдельный раздел **Личные** для ЛС.
- **ЛС не зависят от присутствия**: список собеседников строится по переписке, а не по онлайну, и написать можно тому, кого сейчас нет в сети — сообщение дождётся его в истории.
- **Персистентная история** на сервере (`store.json`, ключуется по каналу и по паре ников для ЛС) - переживает перезапуск. Клиент подтягивает историю канала при открытии.
- **Правка и удаление** своих сообщений (инлайн, автор-онли), пометка «изм.», время у каждого сообщения.
- **Реакции** на сообщения (палитра из 8 эмодзи, тап-чтобы-реагировать, чипы со счётчиком и подсветкой своих, поп-анимация; своя реализация в стиле Telegram, без их GPL-кода/ассетов) - агрегируются по пользователям и персистятся.
- **Ответы** на сообщения (цитата автора+текста над сообщением, клик по цитате - скролл к оригиналу с подсветкой; снапшот ответа переживает удаление оригинала).
- **Вложения**: файлы и картинки, лимит 25 МБ и до 10 штук на сообщение. Картинки показываются инлайн, прочее - карточкой-ссылкой. Подробнее - ниже.
- **Typing-индикатор** по каналу/ЛС и подсветка **@упоминаний** (своё имя выделяется, сообщение помечается).
- **Лента не выдёргивается из-под курсора**: автоскролл только когда ты и так внизу, иначе появляется плашка «новых: N».
- **Обрыв связи не глотает сообщения**: пока сокет мёртв, отправленное копится в очереди (видно в шапке) и уходит после переподключения.
- **Адаптивная вёрстка**: на узких экранах сайдбар уезжает за край, открывается гамбургером; панели звонка/настроек подстраиваются.

## Вложения

Файлы не лежат на диске в открытом виде и не раздаются по угадываемой ссылке.

**Сессия.** При входе сервер выдаёт в `welcome` токен, живущий ровно столько же,
сколько WebSocket-соединение. Он нужен и для `POST /upload`, и для
`GET /uploads/:id`, и передаётся заголовком `Authorization: Bearer`, а не в URL.
Открыть `http://<хост>:3000/uploads/<id>` в браузере не выйдет — вернётся 401.
Клиент забирает вложение через `fetch` и показывает из `blob:`-ссылки.

**Хранение.** Байты сжимаются gzip (если это что-то даёт — уже сжатые jpeg/png
пишутся как есть) и шифруются AES-256-GCM. На диске лежит
`магия | метаданные | iv | tag | шифротекст`, где метаданные (mime, размер,
флаг сжатия) открыты, но входят в AAD — подменить их, не сломав проверку GCM,
нельзя.

**Имя файла = дедупликация.** Блоб называется `HMAC(ключ, sha256(содержимое))`:
одинаковые файлы, залитые хоть десятью людьми, занимают на диске одно место, но
по имени нельзя понять, что внутри (обычный хэш выдавал бы известные файлы).
При чтении хэш пересчитывается — блоб, подложенный под чужой id, не отдастся.

**Доступ.** Скачать вложение может только участник разговора, в котором оно
приложено: картинку из чужого ЛС не вытащить, даже зная id. Размер и mime
берутся из самого блоба, а не из слов клиента. Инлайн отдаются только заведомо
безопасные растровые форматы, всё остальное — как `attachment` + `nosniff`,
чтобы svg/html не исполнились в origin.

**Уборка.** Блобы, на которые не осталось ссылок (сообщение удалили или его
вытеснило из истории), раз в минуту выметаются; свежезалитые не трогаются
полчаса, чтобы не удалить файл, который ещё висит в поле ввода.

## Передача файлов напрямую

Кнопка со скрепкой в шапке открывает панель поверх чата — это встроенный
[lan-drop](../lan-drop): файлы идут между устройствами по WebRTC DataChannel,
минуя сервер. Лимита в 25 МБ, как у вложений, здесь нет, и на диск сервера
ничего не ложится.

Сигналинг живёт на отдельном пути `/drop` того же порта (`noServer` разводит
апгрейды по `pathname`) и **требует сессию**: клиент первым сообщением
предъявляет токен из `welcome`, сервер сверяет его через `Auth.resume` и только
тогда впускает пира в реестр. Без этого сигналинг был бы дырой в обход всего
входа — кто угодно в сети видел бы список устройств и стучался к ним.

Пир называется `ник · устройство` (устройство клиент определяет по UA), поэтому
два открытых окна одного человека различимы. Адресуются именно **устройства**, а
не ники: у одного пользователя их может быть несколько, и файл идёт в
конкретное.

Приём подтверждается вручную, входящее пишется на диск по мере поступления —
подробности в [README lan-drop](../lan-drop/README.md).

## HTTPS (микрофон/камера с других устройств)

Браузеры разрешают микрофон, камеру, `setSinkId` и WebRTC-медиа только в **secure context** — это HTTPS или `localhost`. Поэтому по `http://<ip-хоста>:3000` с чужого устройства микрофон **молча блокируется без промпта**. На самом хосте (`localhost`) всё работает, у остальных — нет.

Решение — поднять сервер по HTTPS с самоподписанным сертификатом (в SAN укажи LAN-IP хоста):

```bash
openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 3650 \
  -subj "/CN=ws-chat" -addext "subjectAltName=IP:192.168.0.29,IP:127.0.0.1,DNS:localhost"
```

(в Git Bash на Windows добавь перед командой `MSYS_NO_PATHCONV=1`, иначе исказится `-subj`.)

Затем укажи пути в `.env` (`TLS_KEY=./key.pem`, `TLS_CERT=./cert.pem`) и запусти. Сервер поднимется на `https://<ip>:3000`, клиент сам переключится на `wss`. На чужом устройстве браузер один раз покажет предупреждение о самоподписанном сертификате — нажать «Дополнительно → Перейти», после чего микрофон заработает.

## Голосовые каналы

Discord-подобные **голосовые каналы** (по умолчанию `general`, `games`; можно создавать новые из сайдбара). Клик по каналу подключает к нему, под каждым каналом видно, кто в нём. Ты в одном голосовом канале за раз; клик по другому переключает.

- Звук — **WebRTC-аудио mesh внутри канала** (каждый шлёт микрофон каждому), Opus поверх UDP/SRTP, минимальная задержка; сервер только релеит сигналинг, медиа через него не идёт. Сигнал ходит только между участниками одного канала.
- Нижняя панель в подключённом состоянии: **mute** (микрофон) и **deafen** (глушит звук всех + свой микрофон), выход.
- `iceServers` пуст: на LAN host-кандидаты, трафик не покидает сеть.
- Mesh рассчитан на небольшую группу; для десятков нужен SFU.
- Демонстрация экрана и громкость-на-участника — следующий заход.

## Приватный звонок

В личке (DM с ником) есть кнопка «Позвонить» - отдельный **1-на-1 звонок в стиле Discord** поверх того же сигналинга: приглашение → входящий баннер с «Принять / Отклонить» → соединение. Звонящий шлёт offer после приёма (нет glare). Если ник не в сети - звонящий получает `call-end` с `reason: offline`; если абонент уже в звонке - автоматический `call-decline` с `reason: busy`.

Панель звонка (справа-снизу, живёт поверх любого канала) показывает:

- **Кто говорит** - зелёное кольцо у активного участника (детект речи через WebAudio `AnalyserNode`, RMS по потоку локально).
- **Аудио-индикатор** - шкала уровня по каждому участнику.
- **Задержку и качество** - из `RTCPeerConnection.getStats()` раз в секунду: RTT (мс), потери, джиттер, битрейт, кодек (opus), и **используемый транспорт** - протокол (UDP/TCP) и типы ICE-кандидатов (`host` / `srflx` / `relay`). Точка слева меняет цвет: зелёная (хорошо) / жёлтая (норм) / красная (плохо).

Всё P2P, `iceServers` пуст - на LAN это host-кандидаты по UDP. Панель звонка можно перетаскивать за верхний хват.

## Настройки

Кнопка-шестерёнка снизу-слева открывает попап:

- **Микрофон / Динамик** - выбор устройств ввода и вывода (`enumerateDevices`; вывод через `HTMLMediaElement.setSinkId`, где поддерживается). Смена применяется на лету в активном голосе/звонке (`replaceTrack`).
- **Эффекты микрофона** - шумоподавление, эхоподавление, автоусиление (constraints `noiseSuppression` / `echoCancellation` / `autoGainControl`).
- **Шрифт** - переключение между JetBrains Mono, Victor Mono, IBM Plex Mono и системным моно. Шрифты забандлены локально (`public/fonts/*.woff2`), работает офлайн.

Настройки хранятся в `localStorage`. Иконки - [akar-icons](https://github.com/artcoholic/akar-icons) (MIT), инлайн-SVG без внешних запросов.

```
  auth.ts       аккаунты (scrypt), сессии, защита от перебора
  blobs.ts      вложения: gzip + AES-256-GCM, дедупликация по содержимому
  jsonfile.ts   атомарная запись и чтение JSON

  chat.test.ts store.test.ts blobs.test.ts  тесты
  server.ts     Express (раздаёт public/, /upload и /uploads) + WebSocketServer
                чата на / и сигналинг lan-drop на /drop
public/
  app.js        клиент чата (каналы, ЛС, история, правка, typing, @упоминания, адаптив)
  voice.js      mesh WebRTC-аудио группового голоса (createVoice)
  call.js       приватный 1-на-1 звонок + индикаторы и статистика (createCall)
  settings.js   попап настроек: устройства, эффекты, шрифт (localStorage)

  vendor/       auto-animate.mjs (@formkit/auto-animate, MIT) - анимация ленты
  index.html styles.css
```

Анимации: появление сообщений через [@formkit/auto-animate](https://github.com/formkit/auto-animate) (MIT, забандлен локально в `public/vendor/`), остальное - CSS-кейфреймы (вход панелей/попапа, пульс входящего звонка и кольца «говорит», ховеры). По умолчанию уважают системный `prefers-reduced-motion`, но в настройках есть переключатель **Анимации: Система / Вкл / Выкл** (`Вкл` форсит их даже при системном «уменьшить движение»).

## Протокол (JSON поверх WebSocket)

Клиент → сервер:

- `{ "type": "auth", "mode": "guest", "nick": "alice" }` — вход без пароля
- `{ "type": "auth", "mode": "register" | "login", "nick": "alice", "password": "…" }`
- `{ "type": "auth", "mode": "resume", "token": "…" }` — поднять сессию после перезагрузки или обрыва
- `{ "type": "logout" }` — гасит сессию; для гостя дополнительно стирает аккаунт и всё написанное
- `{ "type": "channel-create", "name": "dev" }` / `{ "type": "channel-delete", "name": "dev" }` / `{ "type": "voice-channel-delete", "name": "music" }`
- `{ "type": "message", "channel": "general", "text": "…", "replyTo": 5, "attachments": [{ "id": "…", "name": "pic.png", "size": 1234, "mime": "image/png" }] }` (или `"to": "bob"`; `replyTo`/`attachments` опциональны, текст можно опустить при вложении)
- Загрузка вложений вне WebSocket: `POST /upload` (тело - файл, заголовки `X-Filename`, `Content-Type`, `Authorization: Bearer <токен из welcome>`) → `{ id, name, size, mime }`; `id` затем кладётся в `attachments` сообщения. Скачивание - `GET /uploads/:id` с тем же заголовком.
- `{ "type": "history", "channel": "general" }` / `{ "type": "history", "to": "bob" }`
- `{ "type": "edit", "id": 12, "text": "…" }` / `{ "type": "delete", "id": 12 }`
- `{ "type": "react", "id": 12, "emoji": "🔥" }` - переключить реакцию (эмодзи из фикс. палитры)
- `{ "type": "typing", "channel": "general" }` / `{ "type": "typing", "to": "bob" }`
- `{ "type": "voice-channel-create", "name": "music" }`
- `{ "type": "voice-join", "channel": "general" }` / `{ "type": "voice-leave" }` / `{ "type": "voice-signal", "to": "bob", "data": … }`
- `{ "type": "call-invite" | "call-accept" | "call-decline" | "call-end" | "call-signal", "to": "bob", … }`

Сервер → клиент: `welcome` (`{ nick, token, guest }` - токен сессии, он же ключ к HTTP-ручкам вложений), `auth-error` (`{ reason, retryAfterMs? }`), `logged-out`, `purged` (`{ nick }` - пользователь стёрт, выкинуть его сообщения), `channels`, `dms` (`{ list: [{ nick, ts }] }` - собеседники по переписке), `presence`, `message` (с `msg` = `{ id, from, text, ts, edited, channel? , to?, reactions? }`), `history`, `edited`, `deleted`, `reaction` (`{ id, reactions }`), `typing`, `system`, `error`, `voice-channels`, `voice-roster` (`{ channel, users }`), `voice-presence` (`{ channels: { name: [nicks] } }`), `voice-signal`, и зеркальные `call-*` с `from` (плюс `reason: offline / busy`).
