# ws-chat

Чат для локальной сети: текст, голос и файлы напрямую между устройствами.
Страница не делает ни одного внешнего запроса — ни шрифтов, ни аналитики,
ни CDN.

```bash
cd ws-chat
cp .env.example .env
npm install
npm run dev     # http://localhost:3000
```

Адреса, по которым сервер виден с других устройств, печатаются при старте.
Для голоса и звонков с этих устройств нужен HTTPS — `npm run cert`.

## Документация

Полный справочник — **<https://h4root.github.io/webtools/ws-chat/>**.
Там разделами: запуск и переменные окружения, аккаунты и устройства, общение,
голос и звонки, прямая передача файлов, безопасность и модель угроз, разработка.

Исходник страницы лежит в репозитории: [`docs/ws-chat/index.html`](../docs/ws-chat/index.html).

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер с перезапуском при правках |
| `npm start` | Обычный запуск |
| `npm test` | Прогон тестов |
| `npm run typecheck` | Проверка типов |
| `npm run cert` | Самоподписанный сертификат для HTTPS |

## Коротко об устройстве

- TypeScript без сборки (`tsx`), фронтенд — ES-модули без бандлера.
- История, аккаунты, сессии и вложения лежат в `DATA_DIR` (по умолчанию
  `./data`). Переписка и вложения зашифрованы, ключ — в `DATA_DIR/upload.key`.
  **Потеряешь ключ — данные не восстановить.**
- Отправка идемпотентна: сообщение несёт метку, повтор после обрыва сервер
  узнаёт по ней и второй раз не создаёт.
- Логика на сервере пишется через падающий тест; DOM и WebRTC проверяются
  руками. Подробности — в разделе «Разработка» документации.
- В свежем клоне перед `npm run typecheck` поставь зависимости и в
  `lan-drop`: он подключён через `file:`, `tsc` заходит в его исходники, а
  npm по такой ссылке зависимости связанного пакета не ставит. На запуск
  это не влияет — только на проверку типов.

Соседний проект [lan-drop](../lan-drop) встроен сюда панелью передачи файлов.
