# ws-chat-desktop

Десктопный клиент к [ws-chat](../ws-chat): окно к серверу в локальной сети.
Своего сервера внутри нет — как у TeamSpeak, клиент и сервер живут отдельно.

Каркас на [Tauri 2](https://tauri.app): нативная часть на Rust, интерфейс —
системный webview. Собранное приложение весит около 5 МБ, потому что браузер с
собой не тащит.

## Запуск

```bash
cd ws-chat-desktop
npm install
npm run dev      # окно с горячей перезагрузкой
npm run build    # .app и .dmg в src-tauri/target/release/bundle
```

Нужен Rust: `brew install rust` на macOS, [rustup](https://rustup.rs) на
остальных системах.

## Как это устроено

```
ui/            локальная страница ввода адреса (index.html, connect.js, address.js)
src-tauri/     нативная часть: окно, разрешения, сборка
```

Клиент показывает свою страницу — адрес сервера и список недавних. После
проверки адреса окно уходит на сервер, и дальше весь интерфейс приходит
оттуда. За счёт этого клиент не устаревает вместе с сервером: обновился
сервер — обновился и интерфейс, переустанавливать нечего.

Адрес проверяется запросом `GET /health` **из нативной части**, а не из
страницы: у окна свой origin, и браузерная политика не пустила бы запрос к
чужому серверу. Ослаблять сервер ради этого — выставлять CORS наружу — не
стали: тогда любая веб-страница смогла бы искать ws-chat в чужой сети.

## Куда ты подключён

Пока окно на своей странице, заголовок говорит просто `ws-chat`. Как только
оно ушло на сервер, там появляется адрес и состояние связи:

```
ws-chat — 192.168.1.10:3000 · без шифрования
ws-chat — chat.local:8443 · зашифровано
```

Без этого подменённый сервер не отличить от своего: строки адреса, как в
браузере, здесь нет, а форма входа у всех одинаковая.

Вернуться к выбору сервера — меню **Сервер → Сменить сервер**. Там же
обновление страницы. Сочетаний клавиш у пунктов нет намеренно: пока фокус в
webview, macOS до меню их не доносит, и подпись обещала бы несуществующее.

## Что с шифрованием

Клиент помнит, по какой схеме отвечал каждый сервер. Если знакомый адрес,
работавший по https, вдруг предлагает открытое соединение, подключение
останавливается с объяснением: сам по себе сервер так не переезжает, а пароль
по такому соединению уходит целиком видимым.

Самоподписанный сертификат системный webview принять не даст: в wry нет
обработчика проверки TLS, и WKWebView просто откажет в соединении. Поэтому
для шифрования нужен сертификат, которому доверяет сама система — свой
добавь в доверенные, иначе клиент покажет, что сервер не отвечает.

Закрепление сертификата (запомнить отпечаток и ругаться на смену, как ssh)
из-за этого же ограничения пока не сделать: настоящее соединение открывает
webview, а не наш код.

## Границы доступа

Страница сервера **не получает нативных возможностей**. Объект `window.__TAURI__`
в ней виден, но каждый вызов упирается в список разрешений:

```
Command plugin:app|version not allowed by ACL
Command plugin:http|fetch not allowed by ACL
```

Разрешения выданы окну с локальной страницей и не распространяются на чужой
origin (`src-tauri/capabilities/default.json`). Проверено на подставном
сервере, а не взято из документации.

## Расход памяти

Замер на macOS с открытым чатом: около 225 МБ на всё вместе со служебными
процессами WebKit, часть которых система делит с другими приложениями.
Chrome с несколькими вкладками на той же машине — 717 МБ в четырнадцати
процессах. Своего браузера клиент не несёт, поэтому лишнего тут ровно
столько, сколько стоит системный webview.

## Сборка в CI

`.github/workflows/desktop.yml` гоняет тесты на обычном бегунке, а сборку — на
macOS: своего Rust там ставить не надо, он уже есть. Готовый `.dmg` кладётся в
артефакты прогона, а по тегу вида `client-v0.1.0` уходит в релиз.

Приложение **не подписано**. На чужой машине macOS откажется открыть его
двойным щелчком — нужно вызвать контекстное меню и выбрать «Открыть», либо
снять карантин:

```bash
xattr -d com.apple.quarantine /Applications/ws-chat.app
```

Подпись требует платного сертификата разработчика, поэтому пока так.

## Что ещё не сделано

- Вход и регистрация происходят на странице сервера. Перенести форму в саму
  программу, а пароль отправлять по API и держать токен в связке ключей
  системы — отдельная задача, требующая работы и на сервере.
- Сборка под Windows: кросс-компиляции у Tauri нет, нужен отдельный бегунок в
  той же матрице. Собирается ли клиент под Windows — пока не проверено.
- Linux отложен: системный WebKitGTK собирается без поддержки медиапотоков, и
  голос там не заработает без пересборки движка.
